# Depth: an unreadable version is not an old host

The reported failure combined two different facts: a known host below 2.0.508
cannot read the required mask files, while an absent version does not establish
that the host is old. Depth now distinguishes supported, unsupported and unknown
versions locally. Missing or malformed versions display a nonblocking warning;
known old versions retain the same block and update/disable guidance. Recognized
supported versions retain the same feature calls and numerical version policy.

This does not invent a capability or promise compatibility. Unknown hosts attempt
the existing composition, render and mask APIs. Actual SDK failures still reject
the pipeline; the template reports failure once, never a saved success. The Apps
panel shows a nonblocking compatibility warning. The headless template frame
contains the same warning, although the Gallery's generic host toast does not
expose frame content; that progress-display limitation remains C01. Known old
hosts are rejected before checkpoint writes or generation begins. Turning depth
off retains the existing non-depth path.

The complete production module is loaded in the dedicated regression suite. Its
actual canonical local-client adapter initializes from a simulated SDK response;
no helper fragments or host globals are injected. Tests cover missing/null/empty
and malformed versions, known old and supported versions, a real downstream
SDK error response, no false caption application/completion, and unchanged late
cancellation boundaries. Native inference and user Projects are not involved.

This is a template-only candidate. Live UI and real generation on a deliberately
unknown host have not been run by these source-level tests. App/SDK/shared modules,
canvas geometry, words, fonts, masks, layout and model selection are unchanged.
