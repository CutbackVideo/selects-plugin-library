# Gallery: preserve the full photo when automatic cover is unsafe

A successful image face observation can contain no detected faces, or its detected face union can be wider than the fixed tile crop. Keeping centered cover in these two cases can discard people still present in the original raster. The consumer now carries a per-slot `fit:contain` value through planning and both Project input normalization paths. The generated effect receives the full native raster viewport, and its uniform transform fits that raster into the unchanged tile. Changing the scale alone would have retained the old cover viewport.

Manual focus and successful feasible cover focus retain their existing behavior. Every preparation clears old derived fit decisions so a later manual choice or unavailable/failed analysis cannot accidentally reuse a previous automatic containment result. Analysis errors, unsupported hosts, unknown jobs and scope disposal do not become `no-faces`. Original source byte/metadata guards and complete verified authoring remain unchanged. The shared face module and the tile effect source are unchanged.

The original 640×338 test photo becomes 356×188.0125 inside its 356×271 tile, leaving about41.49 pixels above and below. Landscape photos without people can also gain these margins. This is a lossless geometric fallback within the source raster; it neither detects previously missed people nor reconstructs pixels already missing from the original. Partial missed faces can remain undetectable when another face is found.

`tests/gallery_contain_fallback.test.mjs` runs the entire compiled production preparation, serialized authoring, native image plumbing, commit and saved verification, with public SDK/IO boundaries simulated. It asserts full-raster viewport, final displayed size, no stretching, preserved manual/feasible/error paths, stale-decision clearing, scope disposal and same-size byte-replacement rejection before any save. The normal builder generates panel.tsx; shared code and unrelated consumers are untouched. Actual saved application pixels, playback and export remain the integration owner's separate gate.
