# News in One Minute

Turns a news article into a one-minute vertical (1080x1920) news short in an editable Selects Draft.

1. Paste an article link (or the article text) and choose a style. The **Chosun Ilbo** style follows the paper's one-minute news shorts.
2. Before writing, choose **ChatGPT subscription**, **Claude subscription** or **Selects credits**. A connected subscription is selected first (ChatGPT when both are connected); an explicit or last-used choice is remembered for this Project. Connect subscriptions in Settings > Connectors, then refresh the connections in the panel. The app writes a headline and 8-14 narration sentences, then checks every sentence against the article (meaning, numbers, unsupported claims, wording). Each sentence shows the article passage it comes from. Writing, checking, scene planning, feedback revisions, repairs and retries all use the same chosen provider. The selector stays available throughout the workflow. Subscription failures never switch to Selects credits automatically.
3. Review and edit the script, then approve it. Nothing is narrated before approval.
4. The app shows the narration's character count and credits, then makes the narration with the voice you choose. The voice field opens a searchable list with each voice's gender and age (where the server provides them) and a preview button; it lists the voices Selects narration offers, which includes Korean ElevenLabs library voices once the server provides them. The chosen voice is remembered for this Project.
5. It plans a visual for each sentence (article photos with a slow zoom, number callouts, charts, stat and quote cards, text cards). The planner looks at the article images and says what each one shows before placing it.
6. Review the scene plan. The approved script and narration fold into one line each (open them to read or edit). The app builds a preview Draft from the plan ("Preview · <article title>", saved in the Project) and opens it in the viewer on the right. Feedback can replace an article photo, change a scene type, split/merge scenes, or edit colors, illustration, text, layout and animation. Plan requests use the scene planner; graphic requests read the actual placed graphic, including manual edits, and change only the requested scenes. A request beyond the template's controls can edit the scene's graphic code. Focused code changes replace uniquely matching, non-overlapping fragments of the original; ambiguous matches get one repair attempt and never fall back to a full rewrite. The resolved code and normalized values still receive the source-fidelity check. Checking and retrying are shown in the progress status. Script, narration, captions, clip timing, transforms and other tracks stay in place during graphic edits. The edit is checked before one commit; a failed edit or a conflicting manual edit keeps the previous version. Requests that are too large ask you to edit fewer scenes, before making any changes. Manual scene fields are applied with "Update the preview"; custom graphics use their own control definitions. Requests mixing plan changes and graphic-code changes ask for separate requests so neither part is silently dropped.
7. Use this layout: only an up-to-date preview can be confirmed, and it becomes the edit Draft under its final name. It holds frame, headline, scenes, captions and narration as separate clips you can edit. The scene rows then go to each scene on the edit Draft; once the plan changes after that, the rows say they no longer move until a new preview is built.

Subscription limits apply to all BYOS LLM work; these calls do not use Selects credits. Without a connected subscription, Selects credits are selected. If connection status cannot be checked, refresh or choose an available source explicitly. When all AI providers are unavailable, sign in and use editing mode, then refresh. An older Selects app without provider selection asks for an update before running any LLM work.

Scene planning and feedback revisions use the same selected AI as script writing and source checking. Plan revisions retain an existing custom graphic's code when its scene type and sentence grouping stay the same. The host preserves that code; planning and repair prompts carry only scene metadata so a photo or grouping request does not ask the model to copy whole programs. ElevenLabs narration is separate and uses Selects credits. Editing an approved script needs a new narration. Article extraction, photo preparation, text-fit checks, timing, motion graphics assembly and previews run as code; the app does not generate new photos with AI.

New drafts place the background on **V1** and narration on **A1** as one linked Main source, with graphics above it. Both start at the same source origin, so Main splits, trims and moves keep picture and sound together. Narration uses the complete source grid; its actual placed frame count determines the final scene/caption boundary. The linked background continues for a half-second ending hold after narration. Existing drafts keep their track layout when a graphic is edited; narration already on A2 need not be moved.

Resource short ids (`r0`, `r1`, ...) can change when Selects restarts. Before planning or building a candidate, the panel re-reads the saved narration job and checks its Project, Audio type and duration. Older plans reconnect only through a matching saved TTS record. A missing or inconsistent identity stops the build before media writes; it never automatically generates another paid narration. The recovery UI offers a retry through scene planning and an explicit new-narration action with its credit notice. Background and band files are imported again for a full candidate, so old aliases cannot pick an unrelated file; this may add duplicate media entries, but existing resources and drafts are retained. UUID references from public panel reads are validated against the exact Project before use.

An article chart can be redrawn and animated using labels, values, units and periods from the article or its attached image, even when those numbers were omitted from narration. Requests receive a separate source-fidelity check; unreadable or unconfirmed data leaves the current graphic in place. Review the resulting chart against the source before exporting. A generated program is validated by Selects, but AI review does not guarantee editorial accuracy or pixel-perfect output.

If the script, timing or overall layout changes enough to require a full build, the app creates a uniquely named candidate draft and retains the previous edit. Earlier and incomplete candidates appear in the panel with their names, status and an Open button; they are never automatically deleted. A failed candidate does not replace the last complete preview or its plan, and the viewer returns to the complete draft that was on screen immediately before candidate creation, including an older retained version. On a first failure, only the recovery list records the incomplete candidate; it is not promoted to the preview. The host may still activate the newly committed candidate tab: the public SDK has no Draft-tab close operation. On older hosts without graphic program editing, feedback and manual updates use the existing plan workflow and build a separate candidate with the same narration. General edits outside the template catalog require the newer host. Legacy previews without clip identifiers bind only when a graphic has an exact, unique name and time match; an ambiguous target is never guessed. Existing style rules still keep captions on every scene and require a disclaimer only for illustration assets.
