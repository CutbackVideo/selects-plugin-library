# Install Photo Grid Reveal

This experimental Selects plugin builds an editable 1080×1920, 3×7 gallery on the Project frame grid, with timing expressed on a 60 fps reference clock. Each original JPG/PNG stays an Image Resource on its own Video track. Video tiles remain Video Resources; only a selected video shorter than the actual output is extended to a separate cached MP4 that holds its last frame. The gallery is never flattened.

The planner is shared by panel preparation and SDK/agent operations. It keeps exact source seconds separate from rounded reference-frame metadata. For the default duration, 30/50/90 fps Projects need 854 frames of prepared 60 fps video; 853 frames cannot cover their rounded output ends. Imported held videos are checked again using exact seconds. Structural input checks and known BPM timing checks run before bundled asset preparation/conversion. Automatic BPM remains pending until estimation; it must pass the full plan before video conversion or Draft dispatch.

The reference's moving slots are 4, 6, 11, 17, 19, and 21. A matching motion pattern uses Videos in those slots and Images in the other 15. Other mixes are editable but do not reproduce that part of the reference format. If the Project has exactly 15 Images and 6 Videos, the panel can assign them to the observed slot types in one action.

Install `panel.tsx` at `SELECTS_USER_PANELS_ROOT/photo-gallery-no2/panel.tsx` and the files listed in `plugin.json` at `SELECTS_USER_SKILLS_ROOT/photo-gallery-no2/`. The generated panel is ready to install; contributors rebuild it from the repository template with `node build-panel.mjs`. That build also generates the packaged input-facts copy used by the installed operation builder; installation does not depend on repository-wide shared paths.

Nothing else is installed, on macOS or Windows. The panel works through Selects' own file access and its bundled ffmpeg/ffprobe; it runs no shell commands, Python or Node.js. Short-video extension uses the existing shared asset owner under `~/.selects/plugin-data/photo-gallery-no2/held-v3/`. It streams whole-file SHA-256, reserves private source/output paths exclusively, copies and verifies the selected source, then encodes the frozen copy. A complete decoded/hashed output is published under its recipe/content hashes before a bounded atomic index points at it. Identical bytes at different selected paths keep independent source mapping. Ordinary repeats reuse a fully verified cache. Existing held-v2 files and older Draft references are preserved.

Active media jobs receive cancellation when the run/Project/Draft scope ends; the standalone panel also ends its scope when unmounted. Already dispatched filesystem operations may finish. Only the invocation's private staging files are cleaned up; published objects/indexes are not rolled back. A process crash can leave private staging or unindexed complete objects, and automatic garbage collection is not implemented. The optional BPM estimate remains a separate flow: it decodes the first 30 seconds to temporary PCM and removes it; its full lifetime migration is still pending.

Music defaults to the bundled **Unexplored (long ver.) — TAD MILLER**, the selected 39.650–53.866667-second excerpt (14.216667 seconds). The existing common asset feature checks the release's 457,308 bytes and SHA-256, publishes a verified copy under `~/.selects/plugin-data/photo-gallery-no2/assets/<sha256>.mp3`, and uniquely confirms or registers its Audio Resource. Each preparation submits at most one import, then reads Project state; it is not a lock across independent runs. A lost reply can recover a confirmed Resource without resubmission. Installation paths are not newly registered, and older paths/Resources/Drafts are left untouched. Corrupt owned copies are checked and repaired through the canonical atomic file client.

The excerpt must cover the actual rounded Project duration. At 30 fps the 853/60-second reference rounds to 427 frames (14.233333 seconds), beyond the excerpt; bundled music therefore stops before publication/import with a length message. Choose No music, another sufficient Project track, or a shorter duration in the panel. It is never silently looped, padded, sped up or shortened. The same rule applies to other incompatible grids (for example 50/90 fps); 24/25/29.97/60/120 fps pass the current default-duration checks. This does not change the planner's rounding policy.

Manual BPM defaults to 113 to preserve the reference timings; it is a timing control, not a measured BPM of this music. Disable manual BPM to estimate a selected track. Keep the attribution, source, license link, and change notice from [THIRD_PARTY.md](THIRD_PARTY.md) when sharing music or finished videos. The panel displays this credit and the MP3 includes it in metadata.

Normal Create requires the host to advertise a numeric maximum script deadline of at least 120 seconds (client #7847); older hosts stop before preparing assets. It builds a complete working copy and saves it once, then independently verifies the saved properties. Sound-bearing verification needs client #7828. These source changes have not been installed or deployed.

App template runs record ownership under `~/.selects/plugin-data/photo-gallery-no2/template-runs/` using the existing public file SDK and browser hashing/encoding. One run ID admits one authoring owner even across panel remounts. A saved receipt is independently checked and returns the same Draft; a pending, unknown, damaged or changed-input record asks for inspection rather than creating again. A deliberate new app run is an explicit retry. Required saved-result readers are checked before claiming or preparing assets; Music Off does not require unused Audio readers. Ordinary panel Create remains an explicit new operation. Local file ownership is not a distributed lock or a transaction with Draft persistence; imported reusable media have a separate lifecycle.

The current panel uses public original-Image `overlayResource`, Project dimensions and asynchronous file stat/readRange, alongside Video/Audio overlays, effects, transforms and persistence. It uses no internal TimelineMutation or DI service. Both entry paths verify selected originals before music import or video conversion, reobserve them afterward, and recheck Image facts inside placement. These are observations rather than a file lock or complete image decoding. An unsupported host stops with an update message. The canonical connection wrapper contains failed/hung initialization and late replaced-context responses. No Selects client source is changed.

The chat skill and panel share the planner, source-facts feature, input preflight, styling and verification operation. Image placement is exposed through the same public SDK. Short-video preparation and BPM estimation still require the panel's bundled media-tool path. Historical live creation/export records belong to their older versions; they do not verify the current repair in an installed host. Playback remains a separate acceptance gate; see [VALIDATION.md](VALIDATION.md). Do not generalize an older creation run into universal chat/panel parity or end-to-end one-shot reliability.

The panel currently creates a new Draft and offers individual clip editing in the Selects timeline. Automated replacement of one tile in an existing Draft is not yet supported. Never rebuild a Draft without explicit instruction or claim unrelated manual edits are preserved by a replacement operation.

Run `SELECTS_DEV_REPO=/path/to/selects node --test *.test.mjs` from this folder. `hold.test.mjs` and `tempo.test.mjs` also compare the panel's short-video hold and BPM estimate with the former Python helpers in `dev/` when the local machine has ffmpeg and python3 (development only; users need neither). See [VALIDATION.md](VALIDATION.md) for live results and outstanding cases.
