# Four Photo Reveal

Use this plugin when the user asks for the No.14 four-photo format. The four inputs are existing Project JPG/PNG/HEIC Image resources in explicit A/B/C/D order; the output is an editable Selects Draft and, if requested, an exported MP4. Do not turn the source photos into MP4 files. Keep the format's screen geometry, timing, reveal, fullscreen order, and transitions. Photo content, decoration, and optional independent grid/fullscreen framing are user choices. Music defaults to the bundled song "Graceful Resolution" and gives the reference edit: a 7.84 s Draft at 25 fps (196 frames; other rates scale each frame by round(f*fps/25)) with the song on Main from 26.2 s. The four grid photos run 0–113 with the "Fade down" effect preset, then fullscreen A 95–143, B 127–161, D 143–175 and C 161–196 (C with Fade down too); each clip effect keeps the format's own reveal and crossfade timing. Select Music Off for a silent Draft with the single 266-frame reference phrase.

Open the installed **Four Photo Reveal** panel in the user's Project. Load Project photos (empty slots fill in Project order), check that A/B/C/D match the requested order, set any decoration and framing choices, and create a new Draft. The default decoration is none (Heart, Star and Circle remain choices). Keep Music on unless the user requests silence. The panel imports assets/music.mp3 once into the Project and verifies Audio type and full-length availability before creating a Draft. The Draft is created with the song on Main covering the whole Draft; volume and replacement remain native editor controls. If import is still preparing, retry after it finishes; reuse the same imported Resource instead of importing duplicates. Only ask a slot question if the user's choices really are ambiguous. Before importing music or creating a Draft, the panel verifies each selected Image Resource ID, original path and dimensions, then confirms that the original is a nonempty readable file. Missing files and unsuccessful observations have separate, file-specific errors. It repeats the source check before placement. The panel checks that each selected SDK Image Resource still points to the same original Project file, then uses the editor's existing Image placement path for eight separate clips. It rejects an unsupported host instead of silently falling back to still-video conversion. A saved result must include a Draft ID and eight Image clip records. With music enabled, read back exactly one Main music clip covering the whole Draft. Preserve the saved recipe music choice when creating a revised Draft.

Image placement uses the public `selects` SDK through `runScript` and the Draft's `overlayResource` method. No editor-internal placement service or client-code change is used. It is experimental and must be tested against the actual installed app after any host update. If the panel reports a partial Draft ID or uncertain save, inspect that Draft before retrying; never generate duplicate Drafts blindly.

The panel waits for its local SDK connection before starting. If initialization fails or cannot be confirmed within 30 seconds, a hidden app template run reports a safe error and stops without mounting its authoring code. A late connection cannot restart a timed-out or replaced run. A visible standalone panel shows an alert instead.

The create path now prepares Images, effects, graphics and audio in one unsaved working copy, then saves the complete Draft once. It checks the decoration graphic identity, interval and explicit parameters before commit and independently reads those back with the saved Images. It also verifies every Image and graphic intrinsic transform (position, per-axis scale, rotation, anchor, enablement, flips and motion keys) before commit and independently after saving. A reopened app run reuses the same transform evidence; manual changes or missing older evidence require inspection without rewriting the Draft. The same create/recovery paths verify the complete intended Audio set, Resource types/IDs, clip identities, Draft intervals, source routing, volume keys/level and fades before and after saving. Music Off requires an empty sound set without requiring an unused Audio API. This does not verify exact source offsets, original bytes or actual audible content. Program verification also checks every visual clip: ordered/enabled effect stacks, exact effect/graphic source, complete parameters and editable controls. No.14 static preset source comes from a separate unsaved canonical reference. Deduplicated source evidence is checked against the existing journal size limit before commit and read back on remount; old evidence or manual edits never trigger a save replay. These checks do not prove actual rendering or Inspector behavior. A pre-commit failure leaves no new Draft; an uncertain commit response still requires inspection before retrying. App template runs now claim a durable run record before preparation and record the final result inside the same authoring SDK request. Reopening the same run reads back its existing Draft; changed inputs or an active/unknown result require inspection instead of another save. Start a new app run for an explicit revision or retry. Standalone panel actions remain explicit new operations.

For a later one-photo or decoration change, keep the other slot choices from the saved recipe or the visible panel state and create a revised Draft. The previous Draft remains available. If the user specifically asks to change only the decoration on an existing Draft, duplicate that Draft and change only its decoration graphic, then compare the saved non-target clips, effects, transforms, and transitions. Do not ask them to repeat choices already known. This does not promise to copy arbitrary manual edits when rebuilding a new version.

After creation, independently read back the Draft's Image Resource types, clip IDs and ranges, one effect per clip, the fullscreen overlaps on separate tracks (ten frames with Music Off), and separate decoration. The Image path implements the measured crossfades inside those clip effects because this Selects version fails to render native Transition objects attached to Image clips. If the user asks for the resulting video, export the Draft, wait for completion, inspect the MP4 through its final frame, and compare the reference format across the full timeline. A saved Draft or editor preview alone is not export verification. Report the first-pass chat result separately from any later manual repair. The source-format match remains provisional until the full mask and grid-exit acceptance checks pass; see `VALIDATION.md`.
